# Deploying on Render

This repository deploys to Render as a Docker web service. Render builds the
root `Dockerfile`, runs `start.sh` at container startup, applies Django
migrations, and starts Gunicorn on Render's assigned `PORT`.

## Deploy

1. Push the `main` branch to GitHub.
2. In the [Render Dashboard](https://dashboard.render.com/), choose **New**
   then **Blueprint** and select this repository. Render reads `render.yaml`
   from the repository root.
3. Enter values when Render prompts for:
   - `ADMIN_USERNAME`
   - `ADMIN_PASSWORD`
   - `DATABASE_URL`
   - `CLOUDINARY_URL`
4. Create the Blueprint and wait for the first deploy to complete.

`DJANGO_SECRET_KEY` is generated by Render. The service runs with Django debug
mode disabled. The Blueprint uses the existing PostgreSQL service referenced by
`DATABASE_URL`; it does not create or alter a database provider.

## Database URL

Use a complete PostgreSQL connection string, not only the hostname:

```text
postgresql://USERNAME:PASSWORD@HOST:PORT/DATABASE_NAME
```

For an existing Render service, add or replace these variables in **Environment**:

```text
DJANGO_SECRET_KEY=<long random secret>
DJANGO_DEBUG=false
DJANGO_ALLOWED_HOSTS=<your-service>.onrender.com
DATABASE_URL=postgresql://USERNAME:PASSWORD@HOST:PORT/DATABASE_NAME
ADMIN_USERNAME=<admin username>
ADMIN_PASSWORD=<strong password>
CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@CLOUD_NAME
```

Do not place these values in Docker build arguments or commit them to Git.
